## CRITICAL CORRECTION: ARCHITECTURE EXEMPTION

**The current CLAUDE.md states**: "Authentication | JWT + Refresh Tokens | FROZEN"

**This migration REQUIRES** an architectural amendment to replace frozen JWT authentication with Keycloak OIDC.

**Authority**: This migration has been explicitly authorized by the Principal Identity Architect with non-negotiable rules overriding the frozen JWT architecture.

**Post-migration state**: Keycloak becomes the source of truth for ALL authentication. Application JWTs are eliminated entirely.

## 1. PROPER OIDC ARCHITECTURE

### Current (JWT) Flow
```
Frontend → POST /auth/login {email, password}
→ Backend validates credentials, issues app JWT
→ Frontend stores JWT in localStorage
→ Protected requests use Authorization: Bearer {JWT}
```

### Target (Keycloak OIDC) Flow
```
React SPA
→ keycloak-js library
→ Redirect to Keycloak /auth/realms/{realm}/protocol/openid-connect/authorize
   (with code_challenge for PKCE, redirect_uri=http://localhost:3000/auth/callback, client_id)
→ User authenticates at Keycloak (email/password OR Google OR Microsoft)
→ Keycloak redirects to: http://localhost:3000/auth/callback?code=AUTH_CODE&state=STATE
→ Frontend keycloak-js exchanges code for tokens (browser, NOT backend)
→ Keycloak returns: {access_token, id_token, refresh_token, token_type}
→ Frontend stores tokens in memory (access_token) or localStorage (refresh_token)
→ Protected requests use Authorization: Bearer {KEYCLOAK_ACCESS_TOKEN}
→ FastAPI validates token signature against Keycloak JWKS endpoint
→ On token expiry, keycloak-js refreshes using refresh_token (browser-side)
```

### Why NO Backend Token Exchange

**REJECTED ARCHITECTURE**:
- Backend POST /auth/callback endpoint
- Code → token exchange in FastAPI
- Application-signed JWTs issued by backend
- Hybrid JWT system

**REASON**: This pattern creates a secondary identity system parallel to Keycloak. It violates Rule 1 (Keycloak is ONLY identity provider).

**CORRECT ARCHITECTURE**:
- keycloak-js performs authorization code exchange IN THE BROWSER
- Tokens stay in the browser
- Backend only VALIDATES tokens, never exchanges or issues them
- FastAPI is a resource server, not an auth server

### Step 1: Login Redirect (Frontend Initiates)

```javascript

  keycloak.login();  // Redirects to Keycloak authorize endpoint

```

**Keycloak URL generated by keycloak-js**:
```
http://localhost:8081/auth/realms/cloud-flight-simulator/protocol/openid-connect/authorize?
  client_id=cloud-flight-simulator-web
  &response_type=code
  &scope=openid+profile+email
  &redirect_uri=http://localhost:3000/auth/callback
  &state=<random>
  &code_challenge=<PKCE_challenge>
  &code_challenge_method=S256
```

### Step 2: User Authenticates at Keycloak (External)

User logs in at Keycloak UI with:
- Email + Password (local Keycloak users)
- OR Google OAuth
- OR Microsoft Azure AD

Keycloak validates credentials against its identity provider, NOT against application database.

### Step 3: Authorization Code Callback (Keycloak → Frontend)

```
GET http://localhost:3000/auth/callback?code=<AUTH_CODE>&state=<STATE>
```

Frontend receives authorization code in URL.

### Step 4: Code Exchange IN BROWSER (keycloak-js)

```javascript
// In /auth/callback route
useEffect(() => {
  keycloak.init({ onLoad: 'login-required' }).then(authenticated => {
    // At this point, keycloak-js has:
    // 1. Extracted code and state from URL
    // 2. Generated code_verifier for PKCE
    // 3. Made POST to Keycloak token endpoint
    // 4. Received access_token, id_token, refresh_token
    // 5. Stored tokens (access in memory, refresh in localStorage)
    
    // Frontend can now access:
    const accessToken = keycloak.token;
    const idToken = keycloak.idToken;
    const roles = keycloak.tokenParsed.realm_access.roles;
    
    // Call backend /auth/me to create local user
  });
}, []);
```

**CRITICAL**: Token exchange happens IN THE BROWSER. FastAPI is never involved.

### Step 5: First Login Provisioning (Backend)

```javascript
// After keycloak-js obtains tokens, frontend calls:
const response = await fetch('http://localhost:8000/auth/me', {
  headers: {
    'Authorization': `Bearer ${keycloak.token}`  // Keycloak JWT
  }
});
// Response: UserSchema { user_id, email, full_name, role, created_at }
```

Backend `/auth/me` endpoint:
1. Extracts Keycloak JWT from Authorization header
2. Validates signature against Keycloak JWKS
3. Extracts claims: sub (keycloak_id), email, name, realm_access.roles
4. Checks if user exists in local DB by keycloak_id
5. **If NOT found**: Creates local user record
   - user_id: UUID (application-generated)
   - keycloak_id: string (from JWT sub claim)
   - email: from JWT claim
   - full_name: from JWT claim
   - created_at, updated_at: now()
   - last_login_at: now()
6. **If found**: Updates last_login_at
7. Returns UserSchema with application user_id

### Step 7: Token Refresh (Browser Auto-Refresh)

keycloak-js monitors token expiry and auto-refreshes:

```javascript

  onLoad: 'login-required',
  checkLoginIframe: false,
  token: localStorage.getItem('keycloak_refresh_token')
});

keycloak.onTokenExpired = () => {
  keycloak.refreshToken(30)  // Refresh when 30s remaining
    .then(refreshed => {
      if (refreshed) {
        // Store new tokens

      }
    });
};
```

## 3. DATABASE CHANGES REQUIRED

### Changes to `users` table

**REMOVE**: `password_hash` column
- Keycloak owns password storage, hashing, and verification
- Local users table must not duplicate this

**ADD**: `keycloak_id` column
- Type: VARCHAR(255) UNIQUE NOT NULL
- Maps local user_id to Keycloak's subject ID
- Enables lookup of local user when JWT arrives with Keycloak ID

**KEEP**: All other columns
- `user_id`: Application identifier (unchanged)
- `email`: From Keycloak ID token (denormalized for query convenience)
- `full_name`: From Keycloak ID token (denormalized)
- `created_at`, `updated_at`: Track local record lifecycle
- `last_login_at`: Track last successful authentication

**Final schema**:
```sql
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    keycloak_id VARCHAR(255) UNIQUE NOT NULL,
    email VARCHAR(255) NOT NULL,
    full_name VARCHAR(255),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    last_login_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_users_keycloak_id ON users(keycloak_id);
CREATE INDEX idx_users_email ON users(email);
```

### DROP: `refresh_tokens` table

Keycloak manages refresh token lifecycle server-side. Application has no need to store or track tokens.

**Action**: Create Alembic migration to DROP TABLE refresh_tokens CASCADE.

### NO NEW TABLES

Do NOT create:
- `keycloak_tokens` table
- `identity_providers` table
- `user_identities` table
- `user_roles` table
- `oauth_sessions` table

All of these are managed by Keycloak. Application stores only:
1. Local user metadata (for business logic)
2. Audit events (P7)
3. Challenge/mission/evaluation data (other domains)

async def get_current_user(
    authorization: str = Header(None)
) -> UserSchema:
    """
    Validate Keycloak JWT and return application user.
    
    Contract:
    - Consumes: Keycloak JWT from Authorization header
    - Produces: UserSchema
    - Side effect: Provisions local user on first login
    """
    
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="Missing auth header")
    
    token = authorization[7:]  # Strip "Bearer "
    
    try:
        # 1. Validate signature against Keycloak JWKS
        claims = await validate_keycloak_jwt(token)
        
        # 2. Extract claims
        keycloak_id = claims['sub']
        email = claims['email']
        full_name = claims.get('name', '')
        roles = claims.get('realm_access', {}).get('roles', [])
        
        # 3. Lookup or create local user
        db = get_db()
        user = db.query(User).filter(User.keycloak_id == keycloak_id).first()
        
        if not user:
            # First login: create local user
            user = User(
                keycloak_id=keycloak_id,
                email=email,
                full_name=full_name,
                created_at=datetime.utcnow(),
                updated_at=datetime.utcnow(),
                last_login_at=datetime.utcnow()
            )
            db.add(user)
            db.commit()
            db.refresh(user)
            
            # Audit event
            audit_service.write_event(
                db=db,
                event_type="USER_REGISTERED",
                source="AUTH_SERVICE",
                user_id=str(user.user_id)
            )
        else:
            # Update last_login_at
            user.last_login_at = datetime.utcnow()
            db.commit()
        
        # 4. Return UserSchema
        return UserSchema(
            user_id=str(user.user_id),
            email=user.email,
            full_name=user.full_name,
            role=determine_role(roles),  # Map Keycloak roles to app role
            created_at=user.created_at
        )
        
    except JWTError as e:
        raise HTTPException(status_code=401, detail=f"Invalid token: {str(e)}")

const useAuthStore = create((set) => ({
  user: null,
  isAuthenticated: false,
  role: null,
  accessToken: null,  // Keycloak access_token (memory only)
  
  // On app load: check if already authenticated
  initializeAuth: async () => {
    const refreshToken = localStorage.getItem('keycloak_refresh_token');
    if (refreshToken) {
      keycloak.token = localStorage.getItem('keycloak_access_token');
      keycloak.refreshToken = refreshToken;

      }).then(r => r.json());

    }
  },
  
  logout: async () => {
    // Call Keycloak logout
    keycloak.logout();
    
    // Clear local tokens
    localStorage.removeItem('keycloak_refresh_token');
    localStorage.removeItem('keycloak_access_token');
    
    set({ user: null, isAuthenticated: false, role: null });
  }
}));

## 7. USER JOURNEY EXAMPLES

### Happy Path: First-Time Learner Login

1. User visits app: http://localhost:3000
2. React router checks `/auth/callback` route — not reached yet
3. App checks localStorage for `keycloak_refresh_token` — not found
4. Redirect to LoginPage
5. User clicks "Login with Keycloak"
6. keycloak-js redirects to: `http://localhost:8081/auth/realms/cloud-flight-simulator/protocol/openid-connect/authorize?...`
7. User creates Keycloak account: email@example.com / password123
8. Keycloak verifies email (optional, configurable)
9. Keycloak issues authorization code
10. Keycloak redirects to: `http://localhost:3000/auth/callback?code=ABC123`
11. keycloak-js extracts code, exchanges for tokens (in browser)
12. keycloak-js stores:
    - access_token: memory
    - refresh_token: localStorage
    - id_token: memory
13. AuthCallbackPage calls GET `/auth/me` with Authorization: Bearer {access_token}
14. Backend:
    - Validates JWT against Keycloak JWKS
    - Extracts keycloak_id = sub claim
    - Creates local user: (user_id=UUID, keycloak_id=sub, email=email, full_name=name, created_at=now)
    - Writes USER_REGISTERED audit event
    - Returns UserSchema
15. Frontend stores user in Zustand
16. Frontend redirects to /dashboard
17. User sees dashboard, is authenticated

### Happy Path: Returning User Login

1. User visits http://localhost:3000/dashboard
2. App checks localStorage for refresh_token
3. keycloak.init() with stored refresh token
4. keycloak-js refreshes access_token from Keycloak (if expired)
5. keycloak-js stores new access_token in memory
6. App calls GET `/auth/me`
7. Backend finds existing user by keycloak_id
8. Backend updates last_login_at
9. Backend returns UserSchema
10. Frontend stores user, continues session

### Happy Path: Protected Route Access

1. User navigates to `/challenges/start`
2. Frontend makes POST to backend with Authorization header
3. Backend get_current_user dependency validates token
4. Token is valid, user is returned
5. Endpoint proceeds with business logic

### Error Path: Token Expired

1. User is idle for 30+ minutes
2. Frontend makes API request with expired access_token
3. Backend returns 401
4. Frontend interceptor catches 401
5. keycloak-js automatically refreshes using refresh_token
6. keycloak-js stores new access_token
7. Frontend retries original request with new token
8. Request succeeds

### Error Path: Refresh Token Expired

1. User is idle for >7 days
2. Refresh token is expired
3. keycloak.refreshToken() fails
4. Frontend logout() is called
5. User is redirected to LoginPage
6. User must log in again

## 8. SECURITY CONSIDERATIONS

### PKCE (Proof Key for Code Exchange)

keycloak-js automatically implements PKCE:
1. Generates code_verifier (random string)
2. Calculates code_challenge = SHA256(code_verifier)
3. Sends code_challenge to authorize endpoint
4. Sends code_verifier to token endpoint
5. Keycloak verifies code_challenge matches

**Protection**: Prevents authorization code interception attacks

### No Service Account Secrets in Frontend

REJECTED:
- Storing Keycloak client secrets in frontend code
- Service account credentials in frontend

CORRECT:
- Frontend uses public client (no secret)
- PKCE provides security without client secret
- Backend uses confidential client (has secret) for optional admin operations

### Token Storage

**Access Token**:
- Storage: Memory only (lost on page refresh)
- Risk: Slightly less convenient (users re-authenticate on refresh)
- Benefit: XSS cannot steal access tokens

**Refresh Token**:
- Storage: localStorage
- Risk: XSS can steal refresh_token
- Mitigation: Keycloak tokens are short-lived, refresh tokens can be revoked
- Alternative: HTTPOnly cookie (requires CORS setup)

### CORS Configuration

| Risk | Severity | Mitigation |
|------|----------|-----------|
