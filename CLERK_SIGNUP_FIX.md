# Clerk Authentication Fix — Signup Redirect & Email Sync Issues

**Date:** 2026-06-27  
**Issue:** User signup not redirecting back to app; email not synced to database  
**Status:** ✅ FIXED  
**Build:** ✅ Passed  

---

## Problems Identified

### Problem 1: Clerk Redirects to Their Onboarding

**Behavior:** After user signs up, Clerk redirects them to `https://dashboard.clerk.com/` instead of back to your app.

**Root Cause:** The `SignIn` component doesn't have a `signUpUrl` configured, so Clerk uses its default behavior (organization/project setup).

**Fix:** Configure both `SignIn` and `SignUp` components with proper redirect URLs.

---

### Problem 2: User Email Not Synced to Database

**Behavior:** User signs up successfully, but database shows `email=NULL`, causing IAM role grant to fail with:
```
IAM Control Error: 400 The email address of a user in the IAM policy is empty.
```

**Root Cause:** The Clerk SDK fetch fails with Pydantic validation error:
```
NameError: Fields must not use names with leading underscores; 
e.g., use 'pydantic_extra__' instead of '__pydantic_extra__'.
```

This is a Clerk SDK compatibility issue with Pydantic 2.x. The API response includes fields that don't match the SDK's model.

**Fix:** 
1. Extract email/name from JWT claims first (JWT is reliable)
2. Only use Clerk API fetch as fallback if JWT doesn't have the data
3. Don't crash if Clerk API fails — use whatever is available

### Backend Change: Fix Auth Sync Strategy

**File:** `backend/app/dependencies/auth.py` (Lines 89-222)

**Key Changes:**

#### 1. Extract Email from JWT Claims First

```python
# Clerk includes email in the token
jwt_email = claims.get("email")
if not jwt_email and claims.get("email_verified"):
    jwt_email = claims.get("email_address")

# Get full name from JWT
first_name = claims.get("given_name") or ""
last_name = claims.get("family_name") or ""
jwt_full_name = f"{first_name} {last_name}".strip() or None

print(f"[AUTH_SYNC] JWT contains: email={jwt_email!r}, name={jwt_full_name!r}")
```

**Why:** JWT is generated by Clerk and doesn't have the SDK parsing bug. It's reliable.

---

#### 2. Use JWT for Initial User Creation

```python
if not user:
    print(f"[AUTH_SYNC] New user — provisioning from JWT. clerk_id={clerk_id}")

    # Use JWT data directly
    email = jwt_email
    full_name = jwt_full_name

    # Only fallback to Clerk API if JWT is missing email
    if not email:
        print(f"[AUTH_SYNC] Email missing from JWT — attempting Clerk API fetch")
        fallback_email, fallback_name = await _fetch_clerk_profile(clerk_id)
        if fallback_email:
            email = fallback_email
        if fallback_name:
            full_name = fallback_name

    # Create user with whatever we have
    user = User(
        user_id=uuid4(),
        clerk_id=clerk_id,
        email=email,           # ← Now populated from JWT
        full_name=full_name,   # ← Now populated from JWT
        role="LEARNER",
        created_at=datetime.now(timezone.utc),
        ...
    )
```

**Effect:** 
- User email is populated immediately from JWT
- No Clerk SDK call on first login (avoids bug)
- Database shows email right away

---

#### 3. Graceful Fallback on Subsequent Logins

```python
else:
    # For existing users with NULL email/name
    needs_sync = not user.email or not user.full_name
    if needs_sync:
        # Priority: JWT > Clerk API > existing value
        
        # Try JWT first
        if jwt_email and not user.email:
            user.email = jwt_email
        elif not user.email:
            # Fall back to Clerk API
            fallback_email, _ = await _fetch_clerk_profile(clerk_id)
            if fallback_email:
                user.email = fallback_email
```

**Effect:** 
- Doesn't crash if Clerk API fails
- Uses whatever data is available
- Gracefully handles the Pydantic bug

## Technical Architecture

### Auth Flow After Fix

```
User Signs Up on /signup
    ↓
Clerk SignUp component
    ↓
User completes signup on Clerk
    ↓
Redirects to /dashboard
    ↓
Frontend calls GET /auth/me
    ↓
Backend receives JWT with email/name in claims
    ↓
Backend extracts email from JWT (NO SDK CALL)
    ↓
Creates User record with email populated
    ↓
Response includes email → No NULL
    ↓
GCP IAM grant succeeds ✓
```

### JWT Claim Structure

Clerk includes in JWT:
- `sub` — Clerk user ID (clerk_user_xxx)
- `email` — User email address
- `email_verified` — Boolean
- `given_name` — First name
- `family_name` — Last name
- `name` — Full name (sometimes)
- `picture` — Avatar URL
